## Главная новая зацепка

В actions.jsonl control_ms измеряет весь вызов Mouse.act, включая ожидание
Python lock, построение batch, Win32 SendInput и возможное вытеснение потока.
Это не чистое время работы Win32-функции и не frame time игры.

| Статистика | control_ms |
|---|---:|
| Медиана | 0.267 |
| p95 | 0.586 |
| Отправок >100 мс | 4 |
| Максимум | 492.678 |

Все четыре длинные отправки содержали shoot=true:

| Время журнала (Москва) | Длительность, мс |
|---|---:|
| 11:16:11.559 | 408.13 |

| 11:18:17.732 | 411.41 |

Это доказанные остановки пути управления, по длительности похожие на прежние
полусекундные остановки. Совпадение с остановкой рендера CS2 в этой сессии ещё
не установлено. Конкретный удерживающий компонент не найден. Нельзя объявлять
причиной FACEIT, Windows hook, игру или GPU только по этим значениям.

## Следующий замер

Добавлены отдельные lock_ms, build_ms, api_ms и thread CPU time для batch,
а также тайминг отпускания кнопки, которого раньше не было.
Пишутся в input-timing.jsonl и input_timing внутри actions.jsonl.
Поведение SendInput, тип событий, задержки выстрелов, захват, веса и драйверы
не менялись. Это диагностика, не заявленное исправление фризов. 85 тестов прошли.

Для изоляции — тот же локальный матч с неизменными capture/model/visual feed:
сопровождение без автоматических выстрелов (F9), затем с выстрелами.
Ручная стрельба в режиме F9 без автоогня даёт дополнительный контроль,
отделяющий реакцию игры на выстрел от программной отправки кнопки.
Окончательное подтверждение общего фриза требует сопоставления с frame-time
записью; отзыв и тайминг отправки сами по себе её не заменяют.

Возможность задержек в обработчиках низкоуровневых событий описана
[Microsoft](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc),
но наличие и виновность такого обработчика на этом ПК не установлены.
