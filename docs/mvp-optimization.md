# Оптимизация MVP, 24 октября 2026

Модель V7 и разрешение 1280 сохранены. Обучение и разметка не менялись.

## Что изменено

- TensorRT 10.13.3.9 FP16, динамические размеры, batch 1, workspace 1 GiB.
  `auto` использует проверенный engine; SHA256 engine и исходных весов должны
  совпадать с `configs/mvp-runtime.json`. При ошибке загрузки auto возвращается
  к PyTorch. Явный режим tensorrt сообщает ошибку вместо скрытого fallback.
- DXGI копирует непосредственно прямоугольник игрового окна вместо всего
  рабочего стола и дополнительной копии. Буфер принадлежит кадру, очередь не растёт.
- Координаты и оценки переводятся с GPU одним пакетом вместо пяти передач.
- Оверлей по умолчанию выключен. При включении рисуется только новый кадр;
  геометрия окна обновляется только при перемещении/изменении размера.
- Статус на диск обновляется четыре раза в секунду вместо двадцати.
- Именованный mutex не допускает двух панелей v2 с двумя моделями и обработчиками F8.
- Большое движение корректирует 90% ошибки с пределом 1800 отсчётов мыши вместо
  45% и 90 отсчётов. Около цели gain 0.45 вместо 0.18. Выстрел требует двух
  последовательных кадров совмещения. Дальним маленьким целям нужен более точный центр.
- После движения отклоняются кадры, захваченные до его отправки. Большая коррекция
  также ждёт видимого изменения положения цели: обновление одного курсора не
  считается ответом камеры. Малые коррекции не ждут субпиксельного ответа, иначе
  квантование детектора может остановить цикл. Фокус, возраст кадра и отпускание
  кнопки по-прежнему проверяются. F6 останавливает движок.

## Измерения

`scripts/benchmark_mvp.py`: 117 ранее использованных диагностических изображений,
conf 0.35, batch 1, прогретые размеры, декодированные массивы BGR, CUDA synchronization.
Это замер без CS2, захвата экрана, оверлея и кодирования видео; не FPS игры.

| Вариант | Медиана predict, мс | p95, мс |
|---|---:|---:|
| PyTorch FP32, 1280 | 14.24 | 19.91 |
| PyTorch FP16, 1280 | 11.42 | 14.85 |
| PyTorch FP16, 960 | 11.81 | 16.40 |
| TensorRT FP16, 1280 | 5.18 | 9.25 |

Скорость зависит от частот ноутбука и фоновой нагрузки. В раннем отдельном проходе
PyTorch FP32 давал медиану 11.07 мс; коэффициент 2.75 относится к таблице этого прохода.

Для TensorRT сохранилось число matched/FP на каждом из 117 изображений:
newcheck 19/7 (31 GT), check 8/1 (9 GT), test 21/1 (25 GT), IoU >= 0.5 с учётом
класса. Средняя ошибка головы на сопоставленных объектах примерно 3.93/5.10/11.27 px
против 3.94/5.12/11.29 px. Это сохранение диагностического результата, не 95% точность.
На 960 теряются обнаружения, поэтому уменьшение разрешения не выбрано.

48 виртуальных сценариев контроллера: частоты 20/30/60 Hz, два размера кадра,
четыре начальных смещения, две высоты персонажа. Медиана до разрешения выстрела
325 -> 167 мс, p95 850 -> 300 мс, успешное совмещение во всех сценариях.
Это идеализированная камера со свежими измерениями, без задержки модели/Windows/игры.
У настоящей модели на сдвигаемом обучающем кадре: 3/3 условных попадания,
72 шага у исходного контроллера и 33 у окончательного; число шагов включает cooldown,
поэтому его нельзя переводить непосредственно в игровое время наведения.

Оконный симулятор теперь использует Raw Input в собственном окне. Прежняя версия
использовала ускоренные координаты курсора Windows, что искажало большие движения.
Источники старых и новых тестов не следует смешивать. Условный радиус попадания
36.34 px взят как 7% высоты тела; это не настоящий hitbox головы CS2.

## Что ещё не доказано

Итоговый оконный стенд: 90/90 условных попаданий. Медиана от появления цели
до попадания 1142 мс, p95 2868 мс, диапазон 578–6834 мс. Это честная граница
текущего полного цикла: результат 167 мс из идеальной камеры не достигнут
в оконном стенде. Исходный V7 остаётся шумным, особенно при частично обрезанном теле.

Игровой FPS и исчезновение периодических 500 ms фризов ещё не измерены.
PresentMon 2.6.0 из официального GameTechDev/PresentMon вернул access denied:
для ETW нужны дополнительные права. Права, группы и защита Windows не менялись.
При финальном запуске локального Dust2 с -insecure обычный ввод опять вернул
SendInput=0/GetLastError=0, в том числе после обновления окна. Интерактивная проверка
прекращена; причина отказа не установлена. Файлы защиты и настройки безопасности
не менялись. Финальная игровая проверка ускоренного контроллера остаётся отдельным шагом.

Семь тестов контроллера прошли, включая фильтры класса/головы, фокус, возраст кадра,
стабильность, cooldown, точность для мелких целей, быстрое совмещение идеальной
камеры и отсутствие повторной большой коррекции при обновлении только курсора.
F6 проверена в оконном стенде: armed=false, ready=false после остановки.

## Повторение

Установка дополнительных зависимостей:
`tools/uv.exe pip install --python .venv/Scripts/python.exe -r requirements-mvp-optimized.txt`

Экспорт: `.venv/Scripts/python.exe scripts/export_mvp_engine.py`.
После нового экспорта требуется повторная проверка, manifest не переутверждается автоматически.

Сравнение: `.venv/Scripts/python.exe scripts/benchmark_mvp.py --engine runs/pose-v7/weights/best.engine`.
Контроллер: `.venv/Scripts/python.exe scripts/benchmark_mvp.py --controller`.
Исторический контроллер сохранён в `runs/mvp-optimization/baseline_core.py`.
Исходные замеры и подробности: `runs/mvp-optimization/inference.json`, `controller.json`.

Панель: `start-mvp-bots.cmd`. По умолчанию full/auto, 1280, 30 Hz, без оверлея.
Диагностические режимы capture и inference не разрешают наведение/стрельбу даже по F8.
Для сравнения нагрузки в одинаковой неподвижной локальной сцене:
игра без MVP -> capture -> inference без оверлея -> full с оверлеем.
Не запускай несколько панелей: меняй режим и нажимай «Запустить мониторинг».
