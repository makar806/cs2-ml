Единицы QPCTime проверены по TimeInSeconds: это секунды. Интервал длинного кадра — [QPCTime − MsBetweenPresents/1000, QPCTime]. Сопоставление означает пересечение временных интервалов, не причинность.

В v3.26 отдельно есть SendInput на 408,328 мс, вне четырёх длинных Present указанного окна. В v3.31 есть три вызова >100 мс (max 483,612), но парного PresentMon для причинного вывода нет. У старых control/actions часть времени задана wall clock, а packet_ready_at отсутствует: точный бюджет очереди и первого выстрела восстановить нельзя. Новая версия сохраняет capture → inference start/end → packet_ready → decision → input start/end на perf_counter.

В [двух WPR](../wpr-summary.md) потеряно 18 106 235 и 2 539 727 событий. render_switches пуст в извлечённых окнах. Второй baseline уже содержит три длинных кадра. Эти пробелы не позволяют определить ожидание CPU/GPU/драйвера; высокая RAM сама по себе не доказывает подкачку.
