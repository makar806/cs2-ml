# v3.32 — офлайн-исправления управления и проверка передачи

10 ноября 2026. База: `b3833262a70bf2851c164d46fa0fb7a2bf80694e`, ветка `fix/offline-control-v3.32`. Требования — [next-agent-prompt.md](next-agent-prompt.md). Работа выполнена без запуска CS2, чтения её памяти/живых файлов, GSI и изменений драйверов. ОС проверки: macOS arm64, Python 3.11.16. Целевой Windows-ноутбук недоступен.

**Важное ограничение выпуска:** реализованы управление, проверки состояния оружия и калибруемый HUD-конвейер, но полный комплект реальных HUD-примеров отсутствует. Без локальной калибровки `work/hud` основной запускатор сохраняет сопровождение и блокирует огонь. Четыре переданных AK-кадра не дают всех цифр боезапаса, перезарядки, смены оружия и снайперского зума. Нельзя считать выпуск готовой поддержкой всего оружия или подтверждённым исправлением попаданий/фризов в игре.

## Поведение

- Mouse 4 переключает длинную очередь по фронту нажатия. Удержание не переключает повторно. Дистанция, слабая голова и конец одиночной серии не разрешают автоматический спрей. Без захваченной цели разрешена ручная проверка по стене, при известном готовом оружии.
- Начало автоматической серии: один случайный выбор 1/2 с порогом 0,5. Второй одиночный — не раньше 0,20 с после успешной отправки первого, по той же свежей цели внутри зоны. Подтверждённое убийство отменяет второй. Продолжение — одиночные с интервалом 0,25 с. Смена оружия, F7/F8/F9 и явное выключение ручного режима сбрасывают серию.
- Для подтверждённого AK точка наведения — текущий видимый корпус: центр рамки по X и 43% её высоты по Y. При слабой голове рамка остаётся пригодной для сопровождения. Это не восстановление скрытых частей тела. Рамка высотой ≥50% экрана используется только как близкий тестовый сценарий.
- Ручная очередь суммирует следование корпусу по X/Y и отдачу в одной команде. Обычная очередь движения отменяется. Пропавшая/несвежая геометрия прекращает удержание ЛКМ. При остановке отменяются старые движения и состояния фильтра, нужен кадр после остановки: старый план не должен дёргать камеру обратно.
- После исчерпания профиля (3,05 с) режим остаётся включённым, но повтор требует визуально наблюдённого пустого магазина/перезарядки либо роста счётчика патронов, готового оружия и свежего корпуса. Пауза 0,45 с — лишь минимальная задержка повторного старта, не свидетельство перезарядки. Новая очередь по одной стене после завершения магазина автоматически не начинается.
- Alt+Tab, F8 off, F9 off, F6, смена оружия, ошибка ввода и закрытие освобождают синтетический ввод. Возврат фокуса требует F8. Реальные Ctrl-события наблюдаются обычным Windows keyboard hook, injected-события исключаются; hook ничего не перехватывает и не внедряется в игру. Физически зажатый левый Ctrl не отпускается программой. При вмешательстве пользователя автоприседание до конца очереди не возобновляется. Если наблюдатель недоступен, синтетическое приседание отключено.

## Оружие, HUD и отдача

Реально зарегистрирован только `weapon_ak47`. Источник recoil — существующий `configs/recoil/ak47.csv`, Artanis-RCS commit `7387d399`, MIT-уведомление рядом. Исходная чувствительность 2,45, масштаб counts = 2,45 / sensitivity; запускатор использует 0,97. Боезапас допустим только как целое 0…30. Срок годности HUD-наблюдения 0,35 с; геометрии цели по умолчанию 0,10 с. Профиль задаёт одиночную каденцию 0,25 с; для начальной пары действует отдельное требование 0,20 с.

HUD читается CPU из того же кадра захвата с периодом не чаще 0,08 с. Силуэт должен совпасть в двух выборках; калиброванный цвет отделяет иконку от светлого фона. Цифры и состояние ready/reloading имеют отдельные шаблоны и пороги различимости. Повторное использование результата не обновляет возраст источника. Неизвестный HUD, неоднозначное состояние, пустой магазин или неподтверждённый профиль запрещают огонь. Причина видна в существующей строке панели и журнале.

На четырёх переданных 1440×1080 кадрах старый белый силуэт узнавал AK в 3/4; палитра из первого кадра дала 4/4. Медиана одного распознавания силуэта — 1,38–1,41 мс **на этой машине**, без чтения файла; это не стоимость полной готовой HUD-системы на RTX-ноутбуке. Первый кадр — калибровка, остальные три — похожие кадры той же обучающей сессии. [Результат с хэшами](v3.32/hud-probe.json), независимой точности нет.

Пистолет, нож, граната, другие винтовки и оба уровня снайперского зума **не поддержаны как разрешённые профили**: огонь блокируется, AK по умолчанию не подставляется. Фальшивой снайперской чувствительности нет. «Плётка» по материалам однозначно не определена. Для расширения нужны изображения активного оружия/переходов/зумов и проверенный профиль; наличие иконки само по себе не разрешает использовать отдачу AK.

Собственное приседание меняет масштаб **новых приращений** recoil с плавным переходом 0,12 с, сохраняя фазу и накопленное смещение. Коэффициент 0,75 — обратимая гипотеза о перекомпенсации при приседании, не измеренное свойство CS2. Откат: `--crouch-recoil-scale 1`. Автоприседание начинается примерно через секунду. Приседание противника отдельно меняет наблюдаемый корпус, поэтому сопровождение следует вниз. Сочетание реального aim punch и движения корпуса ещё требует записи попаданий.

### Локальная калибровка

`scripts/calibrate_weapon_hud.py` принимает JSON разметки уже сохранённых кадров. Пример структуры (сокращён, нужны все 10 цифр, оба состояния и минимум две разные иконки):

```json
{
  "ammo_roi": [0.74, 0.94, 0.78, 0.99],
  "state_roi": [0.82, 0.94, 0.87, 0.99],
  "samples": [
    {"name": "weapon_ak47", "image": "ready.png", "rect": [0.90, 0.69, 0.98, 0.73]},
    {"name": "weapon_knife", "image": "knife.png", "rect": [0.90, 0.69, 0.98, 0.73]},
    {"name": "digit-0", "image": "ready.png", "rect": [0.76, 0.94, 0.78, 0.99]},
    {"name": "ready", "image": "ready.png", "rect": [0.82, 0.94, 0.87, 0.99]},
    {"name": "reloading", "image": "reload.png", "rect": [0.82, 0.94, 0.87, 0.99]}
  ]
}
```

Координаты нормированы на размер кадра; указанные числа — пример, не готовая калибровка CS2. Для `state_roi` нужен действительно различимый визуальный признак готовности/перезарядки. Если на конкретном HUD такого признака нет, текущий шаблонный вариант недостаточен: потребуется проверенный временной визуальный классификатор. Нельзя выдать отсутствие шаблона за ready или заменить наблюдение таймером.

```text
python scripts/calibrate_weapon_hud.py --annotations work/hud-annotations.json --output work/hud
```

Калибратор не перезаписывает существующую директорию; сохраняет хэши исходных изображений, области и палитру. Снимки и шаблоны остаются в игнорируемом `work/`. Персональный шаблон собственной плашки по-прежнему отдельно: `work/killfeed/self-name.png`. Самостоятельно из архива полный HUD-ready комплект не создан — требуемых наблюдений нет.

## Фризы: что известно

[Таблица всех 45 этапов, восьми live-сеансов и совмещение QPC](v3.32/measurements.md), [машиночитаемый пересчёт](v3.32/measurements.json). SHA-256 публичного архива: `26bc35302a5616e5e6680a0698a3de8a97f56e04846e2e854e021df5e943acef`.

Один capture без модели/ввода уже давал около 0,5 с на DXGI, WGC, MSS, в том числе при запасе около 4 ГБ RAM. В DXGI 30→20→30 было по две паузы на этап; снижение до 20 не доказало устранение. Оконный отдельный прогон был плавным, как и поздний full live при 120 FPS; в полноэкранной серии capture120 первый этап имел три длинных кадра. Отзывы о плавных 220 FPS, тренировочной карте, фризах Dust2/матча с другом и рабочего стола не имеют подтверждённой привязки к тем же синхронным измерениям.

В общей QPC-шкале 9 длинных кадров v3.25 и 4 v3.26 не пересеклись с SendInput >100 мс. Один медленный input408 мс v3.26 лежит вне этих окон. v3.31 содержит три input >100 мс, max483,612 мс, без парного PresentMon. Причинный механизм графической/системной паузы по этим данным не установлен. WPR потерял 18 106 235 и 2 539 727 событий; во втором baseline три паузы уже без capture. Нет оснований объявлять виновными драйвер, античит, подкачку или гибридную графику.

Выбранные локальные гипотезы: синхронный I/O мог удлинять control-loop, заимствованный WGC-буфер мог менять изображение во время обработки, незавершённый close мог пересекать поколения capture. Исправления проверены отдельно и не объясняют все исторические capture-only фризы. `--sync-logs` возвращает синхронный журнал для A/B; остальные небольшие изменения изолированы в соответствующих модулях. Очереди по-прежнему ограничены одним последним packet/кадром, старый source не разрешает огонь. AsyncLog ограничен 4096 строками на файл, переполнение/ошибки отражаются в `input_log_health`, packet `worker_log_health` и финальном `worker-log-health.json`.

Нужны последующие одинаковые A/B на целевом ноутбуке: фиксированная карта, режим экрана/FPS, baseline/capture/inference/full; QPC PresentMon + новые stage timestamps; RAM/commit/page faults и wait/GPU events без массовой потери ETW; отдельные кадры HUD/плашки во время пауз. Сначала лёгкий сбор, тяжёлый WPR отдельным контролем. В этой работе новые игровые замеры не запускались.
