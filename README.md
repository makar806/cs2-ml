## Обработка видео

Для V3 явно укажите `--weights runs/pose-v3/weights/best.pt --model-label V3 --filename result-v3.mp4`.
Размер входа задаётся `--imgsz` (по умолчанию 640); исходный звук можно скопировать `--keep-audio`.
По умолчанию сохранено прежнее поведение V2 без звука.

`scripts/annotate_video.py SOURCE --output OUTPUT_DIR` обрабатывает все кадры
весами `runs/pose-v2/weights/best.pt` и сохраняет H.264 MP4, JSONL-предсказания,
выборочные кадры и сводку. Использует imageio-ffmpeg. Пример запуска:
`.venv\Scripts\python.exe scripts\annotate_video.py "C:\path\clip.mp4" --output "C:\path\new-output"`.
Видео сохраняется без звука с усреднённым исходным FPS; временная структура
VFR не воспроизводится точно. Исходник не изменяется. Папка с готовым MP4 не перезаписывается.

Команда: `train-pose.cmd --data configs/pose-v3.yaml --name pose-v3`.
Отчёт после оценки: `docs/third-pose-run.md`.
Запись, использованная для разметки этих кадров, теперь относится к обучающим данным,
включая её соседние кадры: для независимой проверки снимите другую сессию.

Второй набор: `data/pose-v2`, конфиг `configs/pose-v2.yaml`.
Добавлены 100 вручную размеченных веб-кадров из `internet_batch_001`.
Train 127 / val 24 / test 12; старый test проверен побайтово и оставлен прежним.
Сессия веб-источника `20260725-185119-fc031b` целиком отведена под val.
Команда второго запуска: `train-pose.cmd --data configs/pose-v2.yaml --name pose-v2`.
Оценка: `.venv\Scripts\python.exe scripts\evaluate_pose.py --run pose-v2 --eval-name pose-v2-test`.
Сводка после оценки: `docs/second-pose-run.md`.

Проект Label Studio ML_CS: 63 размеченных оригинала 1440×1080,
108 T и 53 CT, по одной привязанной точке головы на персонажа.
`scripts/audit_annotations.py` читает базу без изменений, проверяет связи и сохраняет JSON-снимок.
`scripts/prepare_pose.py` конвертирует последний снимок в YOLO Pose,
проверяет координаты, размеры, дубликаты и связи точек с рамками.
Приняты 0=T, 1=CT, одна точка Head, kpt_shape=[1,3].

Набор `data/pose-v1`: train 45 кадров (97 T/27 CT), val 6 (2 T/10 CT),
test 12 (9 T/16 CT). Разделение фиксировано по хронологическим сценам:
ранние сцены / эпизод в тоннеле / поздние уличные сцены.
Это предварительная проверка в пределах одной вечерней съёмки, а не независимый
тест на новой игровой сессии: фон, модели персонажей и настройки коррелируют.
Почти соседние кадры не перемешиваются случайно; границы сцен и происхождение
записаны в `data/pose-v1/manifest.json`. Для отчётных метрик собрать отдельную сессию.
Нет пустых обучающих кадров; ложные срабатывания на фоне пока плохо проверены.

`train-pose.cmd` запускает YOLO11n-pose, 60 эпох максимум, batch 8, 640 px,
seed 42, early stopping patience 20. Веса: `runs/pose-baseline/weights/best.pt`.
Конфигурация: `configs/pose.yaml`; фактические параметры: `runs/pose-baseline/args.yaml`.
Исходный детектор из `train.cmd` не обучает точку головы — для текущего датасета нужен train-pose.cmd.
`scripts/evaluate_pose.py` оценивает best.pt на test и сохраняет JSON и изображения.
Ошибка головы считается в исходных пикселях только для правильно классифицированных
и сопоставленных рамок при conf>=0.25, IoU>=0.5; её надо читать вместе с recall.
Pose mAP использует стандартную для custom keypoints нормировку OKS Ultralytics.
Измеренная встроенным валидатором скорость не является задержкой всей системы.

Формат: https://docs.ultralytics.com/datasets/pose/

## Сбор изображений

Сохраняйте оригинальные скриншоты PNG/JPG в `data/raw/session_001/`.
Для новой игровой сессии создайте новую папку `session_002` и т.д.
Собирайте разные дистанции, ракурсы, фон, обе команды и пустые сцены.
Не рисуйте рамки на самих изображениях и не уменьшайте их заранее.

## Разметка

Запустите `start-labeling.cmd`, затем откройте http://127.0.0.1:8080.
Создайте локальную учётную запись и проект CS2 T-CT.
Импортируйте скриншоты. В Settings → Labeling Interface → Code вставьте
содержимое `configs/labeling.xml`. Размечайте каждого видимого живого персонажа:
T — террорист, CT — контртеррорист. Свои руки, оружие и трупы не размечайте.
При перекрытии рамка охватывает видимую часть персонажа; не угадывайте скрытые границы.
Если команду нельзя определить, отложите кадр для проверки, не угадывайте.
Пустые кадры сохраняйте с пустой разметкой.
Экспортируйте YOLO с изображениями. Проверьте экспортированный classes.txt:
проект использует 0=T, 1=CT; при другом порядке нужно преобразовать метки.
Исходные сессии храните отдельно даже после импорта.

## Обучение

Окружение обучения: `.venv`, разметки: `.venv-labeling`.
`check-environment.cmd` проверяет импорты и реальное вычисление на GPU.
Данные после экспорта нужно разделить по исходным сессиям на train/val/test:
`data/dataset/images/{train,val,test}` и `data/dataset/labels/{train,val,test}`.
Не разделяйте случайно соседние кадры одной сессии между выборками.
После подготовки данных запустите `train.cmd` (50 эпох, batch 8, 640 px).
При нехватке видеопамяти: `train.cmd --batch 4`.
Обучение не запускается до появления размеченных данных.
Базовые веса `models/yolo11n.pt` обучены на общих объектах, а не на T/CT.

Полный CUDA Toolkit для запуска готовых пакетов PyTorch не требуется.
Драйверы не изменялись. Датасет, окружения и веса исключены из Git.
