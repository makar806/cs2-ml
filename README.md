# CS2 ML MVP

Учебный проект по компьютерному зрению: обнаружение T/CT, определение точки
головы и управление в контролируемом локальном матче с ботами.
Здесь опубликован один актуальный срез MVP 3.7 и текущие веса V7.

## Что работает

- YOLO11n-pose: рамка персонажа, класс `T`/`CT`, одна точка `Head`.
- Захват экрана через DXGI; WGC доступен как альтернатива.
- Отдельный процесс распознавания, очередь только последнего результата.
- Выбор цели по всему кадру, геометрическое сопровождение и коррекция мыши.
- Быстрый первый захват, сглаженные последующие поправки, интервал выстрелов.
- Экспериментальное подтверждение убийства по собственной плашке на экране.
- Опциональный TensorRT FP16 без импорта PyTorch в процессе распознавания.

Управление проверяется только в локальном матче с ботами. Приложение не
определяет автоматически тип сервера. Прототип не предназначен для онлайн-матчей.
Обычный ввод Windows не гарантирует совместимость с античитами.

## Состояние проекта

MVP работает, но пока есть периодические фризы, дрожание наведения и пропуски
маленьких/плохо видимых персонажей. Отсутствие фризов и качество 95% не достигнуты.
Тесты контроллера не являются проверкой качества модели или производительности игры.

Последний датасет: 600 изображений, в том числе пустые кадры; 375 train,
108 val, 117 в трёх проверочных поднаборах. Разметка сделана в локальном
Label Studio: рамка T/CT и связанная точка головы. Часть предварительных
разметок модели проверялась вручную. Исходники датасета в репозиторий не включены.
Разбиение учитывает сцены и игровые записи; исходный маленький test содержит
кадры одной вечерней съёмки и не является независимой новой игровой сессией.

На валидации V7 (108 изображений, 77 персонажей): box mAP@50 = 0.819,
box mAP@50:95 = 0.565, pose mAP@50 = 0.783. Это сохранённые результаты обучения,
а не оценка всей системы в игре. Повторно просмотренные диагностические наборы
использовались при выборе настроек; для итоговой оценки нужна новая сессия.

## Установка

Проверенная среда: Windows 11, Python 3.11, RTX 4060 Laptop 8 ГБ,
PyTorch 2.11.0 CUDA 12.8, Ultralytics 8.4.178. Для живого MVP нужна NVIDIA GPU.
Офлайн-проверка изображения/видео поддерживает CPU.

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Веса `models/best.pt` уже включены. Это дообученная YOLO11n-pose,
а не исходная COCO-модель. Файлы PyTorch следует загружать только из доверенного источника.
Драйверы и настройки Windows установочные команды не меняют.

## Проверка изображения или видео

```powershell
.venv\Scripts\python.exe scripts\predict.py path\to\video.mp4
.venv\Scripts\python.exe scripts\predict.py path\to\image.jpg --device cpu
```

Результаты сохраняются в `runs/predictions*`. В этом режиме мышь не управляется.

## Запуск локального MVP

Запустить `start.cmd` или:

```powershell
.venv\Scripts\python.exe scripts\live_mvp.py --mode local-bots --death-source manual --autostart
```

В CS2 открыть локальный матч с ботами. В панели указать свою игровую
чувствительность и команду противника. Значение sensitivity по умолчанию — 0.97,
это настройка разработчика, а не универсальная калибровка.
Тестовый профиль: безрамочный полный экран 1920×1080, вход 960, до 30 Гц.
Увеличение входа до 1280 сохраняет больше деталей, но увеличивает нагрузку.

После «Готово» вернуть фокус игре:

| Клавиша | Действие |
|---|---|
| F8 | Включить/выключить управление |
| F9 | Переключить сопровождение без выстрелов / с выстрелами |
| F7 | Отпустить текущую цель |
| F6 | Остановить движок |
| Alt+Tab | Отключить управление при потере фокуса |

Без готового локального TensorRT engine режим `auto` использует PyTorch.
Журналы работы пишутся в `runs/live-mvp/`, в Git они не попадают.

### TensorRT FP16

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-tensorrt.txt
.venv\Scripts\python.exe scripts\export_engine.py
```

Engine собирается на целевом компьютере; готовые TensorRT-бинарники между
компьютерами не переносятся. Скрипт проверяет загрузку и декодирование выхода,
сохраняет хеши engine/весов. Это smoke test, не новая оценка mAP.
После экспорта `auto` выбирает native TensorRT.

### Плашка убийства

По умолчанию сброс цели ручной, F7. Для автоматического сброса нужен собственный
шаблон ника: сохранить скриншот с собственной плашкой убийства при игре за CT и выполнить:

```powershell
.venv\Scripts\python.exe scripts\calibrate_killfeed.py path\to\screenshot.png --row 0
```

Затем выбрать `visual` в панели. Шаблон остаётся локально в `work/killfeed/`.
Распознавание зависит от цвета/масштаба HUD и не устанавливает точную личность
убитого персонажа. Оно может ошибаться; ручной сброс остаётся доступным.

## Код

| Файл | Назначение |
|---|---|
| `scripts/live_mvp.py` | Панель, горячие клавиши, связь процессов и отправка действий |
| `scripts/mvp_runtime.py` | Цикл захвата и распознавания, ограничение частоты, выбор движка |
| `scripts/mvp_core.py` | Отбор цели, удержание, расчёт коррекции и решения о выстреле |
| `scripts/mvp_motion.py`, `mvp_geometry.py` | Сглаживание и учёт движений камеры между кадрами |
| `scripts/mvp_windows.py` | Win32: окно, фокус, горячие клавиши и SendInput |
| `scripts/mvp_capture*.py`, `mvp_wgc.py` | Захват изображения и его жизненный цикл |
| `scripts/mvp_native_trt.py` | TensorRT/CUDA и декодирование рамок/точек головы |
| `scripts/mvp_killfeed.py` | Экспериментальное распознавание собственной плашки убийства |
| `scripts/mvp_metrics.py` | Диагностика памяти и нагрузки |
| `scripts/train.py`, `evaluate.py`, `predict.py` | Обучение, оценка и офлайн-предсказания |
| `configs/labeling.xml` | Схема разметки Label Studio |

Нейросеть выдаёт геометрию и классы. Управление реализует отдельный алгоритм;
обучения управлению с подкреплением или imitation learning здесь нет.

## Обучение и тесты

Свой датасет разместить в `data/dataset/images/{train,val,test}` и
`data/dataset/labels/{train,val,test}`. Одна строка YOLO Pose:
`class cx cy width height head_x head_y visibility`, координаты нормированы.
Классы: `0=T`, `1=CT`; `kpt_shape=[1,3]`. Неразличимая голова имеет visibility=0.
Не смешивать соседние кадры одной записи между train и проверкой.

```powershell
.venv\Scripts\python.exe scripts\train.py
.venv\Scripts\python.exe scripts\evaluate.py --split test
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Для нового обучения от исходной модели: `scripts\train.py --weights yolo11n-pose.pt`.
Текущий датасет не опубликован, поэтому обучение и исторические метрики без него
не воспроизводятся одним клонированием. Тесты используют синтетические объекты
и подменённые Windows API; к игре не подключаются и мышью не управляют.

Используются Ultralytics YOLO и её предобученная модель; условия сторонней
лицензии AGPL-3.0/Enterprise см. в [Ultralytics](https://github.com/ultralytics/ultralytics).
